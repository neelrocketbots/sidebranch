Features

In-page branch switching — pick any branch from the pill; it builds in an isolated worktree on its own dev server.
Side-by-side compare — both panes live, one width control drives both viewports in lockstep (375 / 768 / 1280).
Blend diff — panes stacked with mix-blend-mode: difference. Identical pixels go black, any change glows.
Onion diff — panes stacked with an opacity slider, for catching layout shifts by eye.
Your working tree, never touched — reads only. No stash, no reset, no checkout; every mutation happens in worktrees under ~/.sidebranch.
Framework-agnostic — if a command can start it and it answers HTTP on a port, it works. Next, Vite, Django, Rails, static.
Lockfile-aware installs — dependencies reinstall only when a lockfile's content hash actually changes.
Loopback-only — binds 127.0.0.1, bearer-token auth, Host and Origin gated. Nothing ever leaves your machine.
Zero dependencies — the entire tool is Node builtins. What you audit in the repo is everything that runs.
A real lifecycle — stop the daemon from any terminal, clean stale worktrees safely, and let doctor check your setup.

Installation

$ cd your-repo
$ npx sidebranch init     # writes .sidebranch.json — edit for your stack
$ npx sidebranch start    # daemon on http://127.0.0.1:49400

Add the widget to your app, dev builds only:

<script src="http://localhost:49400/widget.js" defer></script>

If the tag ever ships to production anyway, it is harmless: the widget refuses to run on non-localhost pages, and a daemon only ever answers loopback requests. With the extension, this step disappears entirely.

Tell it how to run your app (.sidebranch.json):

{
  "dev": "npm run dev",        // start command, run inside each pane
  "install": "npm install",   // runs only when lockfiles change
  "copy": [".env", ".env.local"]
}

Then click the pill, pick a branch, and compare. Full configuration reference, recipes for complex apps, and the threat model live in the README and SECURITY.md.
